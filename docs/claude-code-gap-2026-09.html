重点差距与建议

P0 高价值 Hooks 生命周期钩子
Claude Code 注册 24 个生命周期事件（CwdChanged / FileChanged / StopFailure / PostCompact / InstructionsLoaded 等）执行 shell 命令，实现「文件变更后自动格式化 / 任务完成通知 / 错误上报 / 压缩后回调」。这是工程自动化价值最高的缺口。
建议：appserver 层加 hooks 表（event → shell 命令），在 codex 消息流转的对应节点触发；复用现有审批规则引擎做白名单约束。
P1 Agent 层三件套：内置专用子代理 / Agent Teams / Background Agents
Claude Code 的 Explore（Haiku 快读只读分析）与 Plan（研究）子代理有明确角色与模型分派；Agent Teams 支持多智能体协调（TeamCreate/SendMessage）；Background Agents 后台并行。
建议：先做「内置 Explore/Plan 角色」+「模型分派」（成本低、复用现有子代理通道），再做团队协调。
🔶 部分 auto 权限的 ML 分类器
你多次强调「deny 应该先判断再执行」，flydex 已用规则引擎实现（优于逐条弹窗）；Claude Code 的 auto 模式用 ML 分类器预判危险度。规则版已达成核心目标，ML 是增强项。
建议：暂不引入本地 ML；可先把规则覆盖面（危险命令白名单）做全，达到同类安全性。
P2 Skills 市场 / Tasks API / Session Forking
Skill 市场带来生态；Tasks API 是持久任务与依赖；Session Forking 是并行时间线。
建议：Skills 市场可做成「从本地 skill 目录导入/导出」，低成本获得生态雏形。
事实口径：Claude Code 能力清单来自 2026 年公开资料（Anthropic 官方文档 / 社区指南，搜索核验）；flydex 现状来自本项目 work-plan 阶段 6 实际落地记录。矩阵为对齐度评估，非官方认证。
